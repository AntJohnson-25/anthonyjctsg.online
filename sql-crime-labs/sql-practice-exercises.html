Rookie: SQL practice for beginners

Start here if you are new to SQL. These nine cases use one table at a time and build up SELECT, WHERE, AND/OR, IN, LIKE, ORDER BY, LIMIT, DISTINCT and your first aggregates. You only need to know what a table and a column are.

1. Pull the watch-list Rookie

select · database: World Watch-list

Case request: the task force wants a printed watch-list of every suspect on file. Pull each suspect's first_name, last_name and role.

Hint

You need every row, so no WHERE clause. Name the three columns after SELECT, separated by commas, then say which table with FROM suspects.

Show the solution and expected output
SELECT first_name, last_name, role
FROM suspects;

Why it works: SELECT picks the columns, FROM picks the table. With no WHERE, every row comes back, which is why all 40 suspects stepped up to the evidence table.

Other databases: Identical in PostgreSQL, MySQL, SQL Server and Oracle.

Case request: which suspects carry a bounty of more than 150,000? Return first_name, last_name and bounty_usd.

3. New faces in Brazil Rookie

whereand · database: World Watch-list

Case request: find suspects in country 1 (Brazil) who first appeared on or after 2021-01-01. Return first_name and first_seen.

Hint

Two conditions joined with AND: country_id = 1 AND first_seen >= '2021-01-01'. Dates are stored as text here, so the date needs quotes.

Show the solution and expected output
SELECT first_name, first_seen
FROM suspects
WHERE country_id = 1
  AND first_seen >= '2021-01-01';

Why it works: AND needs both conditions to be true. ISO dates (YYYY-MM-DD) sort the same way as text and as dates, so >= works on them.

Other databases: SQLite stores dates as text. PostgreSQL/MySQL/SQL Server have real DATE types but accept '2021-01-01' the same way. Oracle prefers DATE '2021-01-01'.

5. Smuggler sweep Rookie

wherelike · database: World Watch-list

Case request: find everyone whose role contains the word Smuggler (Senior Smuggler, Junior Smuggler, Chief Smuggler...). Return first_name, last_name and role.

Hint

LIKE matches patterns. % stands for any run of characters, so '%Smuggler%' means Smuggler anywhere in the role.

Show the solution and expected output
SELECT first_name, last_name, role
FROM suspects
WHERE role LIKE '%Smuggler%';

Why it works: LIKE '%Smuggler%' matches Smuggler with anything before or after it. That catches Chief Smuggler, Senior Smuggler and Junior Smuggler along with plain Smuggler.

Other databases: LIKE is case-insensitive in SQLite and MySQL but case-sensitive in PostgreSQL (use ILIKE there) and in Oracle.

6. Mid-value evidence Rookie

betweenorder · database: Port Evidence Room

Case request: list the name and street_value of contraband worth between 20 and 60 (inclusive), cheapest first.

Hint

WHERE street_value BETWEEN 20 AND 60 includes both ends. Then ORDER BY street_value sorts ascending (cheapest first) by default.

Show the solution and expected output
SELECT name, street_value
FROM contraband
WHERE street_value BETWEEN 20 AND 60
ORDER BY street_value;

Why it works: BETWEEN a AND b is the same as >= a AND <= b. ORDER BY sorts ascending unless you add DESC. Without ORDER BY, SQL doesn't promise any particular order.

7. Most wanted five Rookie

orderlimit · database: World Watch-list

Case request: show the 5 highest bounties on file: first_name, last_name, bounty_usd, highest first.

Hint

Sort with ORDER BY bounty_usd DESC so the biggest bounty comes first, then keep the first five rows with LIMIT 5.

Show the solution and expected output
SELECT first_name, last_name, bounty_usd
FROM suspects
ORDER BY bounty_usd DESC
LIMIT 5;

Why it works: ORDER BY ... DESC puts the biggest values first and LIMIT cuts the list off. LIMIT applies after sorting, which is why you get the top five and not five random rows.

9. Bounty snapshot Rookie

aggregate · database: World Watch-list

Case request: the director wants three numbers in one row: suspects (how many are on file), total_bounty (sum of all bounties), and avg_bounty (average bounty, rounded to a whole number).

Hint

Aggregates squash many rows into one: COUNT(*), SUM(bounty_usd), ROUND(AVG(bounty_usd)). Name each one with AS.

Show the solution and expected output
SELECT COUNT(*) AS suspects,
       SUM(bounty_usd) AS total_bounty,
       ROUND(AVG(bounty_usd)) AS avg_bounty
FROM suspects;

Why it works: Aggregate functions summarize the whole table into a single row. AS gives each result column a readable name.

Other databases: ROUND(x) works in all major databases. SQL Server needs ROUND(x, 0), and its AVG of an integer column returns an integer, so cast to DECIMAL first when you need the exact average.

Expected output (any row order):

suspectstotal_bountyavg_bounty
404,324,000108,100

10. Suspects by country Semi-Pro

groupnull · database: World Watch-list

Case request: for each country_id, return the country_id and a headcount of suspects. Two hired guns have no country on file (country_id is NULL); leave them out.

Hint

GROUP BY country_id makes one row per country; COUNT(*) counts the rows in each group. Filter the stateless suspects first with WHERE country_id IS NOT NULL.

Show the solution and expected output
SELECT country_id, COUNT(*) AS headcount
FROM suspects
WHERE country_id IS NOT NULL
GROUP BY country_id;

Why it works: GROUP BY splits the rows into buckets and the aggregate runs once per bucket. Each tower is one bucket. NULL is never equal to anything, so you test it with IS NULL / IS NOT NULL.

Other databases: Identical everywhere.

11. Who works where Semi-Pro

join · database: World Watch-list

Case request: return each suspect's first_name, last_name and their country's name (call it country). Stateless suspects don't appear.

12. Every country counts Semi-Pro

joinleft joingroup · database: World Watch-list

Case request: list every country's name and its headcount of suspects, including countries with nobody on file (they should show 0).

Hint

Start FROM countries and LEFT JOIN suspects so empty countries survive. Count a column from suspects, COUNT(s.suspect_id), not COUNT(*), or empty countries count as 1.

Show the solution and expected output
SELECT c.name, COUNT(s.suspect_id) AS headcount
FROM countries c
LEFT JOIN suspects s ON s.country_id = c.country_id
GROUP BY c.country_id, c.name;

Why it works: LEFT JOIN keeps every row from the left table even with no match, filling the right side with NULL. COUNT(column) skips NULLs, so Germany correctly gets 0. COUNT(*) would count its one NULL-filled row.

Other databases: Identical everywhere. Some databases require every non-aggregated column in GROUP BY, so grouping by both id and name is the portable habit.

Expected output (any row order):

15. Threat tiers Semi-Pro

case · database: World Watch-list

Case request: tag every suspect. Return first_name, bounty_usd and tier: 'Most Wanted' for 130,000 and up, 'Wanted' for 80,000 and up, otherwise 'Watch'.

Hint

CASE WHEN bounty_usd >= 130000 THEN 'Most Wanted' WHEN bounty_usd >= 80000 THEN 'Wanted' ELSE 'Watch' END AS tier. The first true WHEN wins, so check the biggest threshold first.

Show the solution and expected output
SELECT first_name, bounty_usd,
       CASE WHEN bounty_usd >= 130000 THEN 'Most Wanted'
            WHEN bounty_usd >= 80000 THEN 'Wanted'
            ELSE 'Watch' END AS tier
FROM suspects;

Why it works: CASE is SQL's if/else. It checks the WHEN conditions top to bottom and stops at the first true one. That's why the order of the thresholds matters.

Other databases: Identical everywhere. SQL Server also has IIF() and MySQL has IF(); CASE works in all of them.

16. Seizures per month Semi-Pro

dategrouporder · database: Port Evidence Room

Case request: for seizures made in 2024, return the month as text like 2024-03 and the number of seizures that month (seizures), in calendar order.

Hint

In SQLite, strftime('%Y-%m', seized_date) turns a date into '2024-03'. Filter 2024 with WHERE, GROUP BY that month, ORDER BY it.

Show the solution and expected output
SELECT strftime('%Y-%m', seized_date) AS month, COUNT(*) AS seizures
FROM seizures
WHERE seized_date >= '2024-01-01' AND seized_date < '2025-01-01'
GROUP BY month
ORDER BY month;

Why it works: You can group by a computed value. The month string sorts correctly because the year comes first and the month is zero-padded.

Other databases: PostgreSQL: to_char(seized_date, 'YYYY-MM'). MySQL: DATE_FORMAT(seized_date, '%Y-%m'). SQL Server: FORMAT(seized_date, 'yyyy-MM'). Oracle: TO_CHAR(seized_date, 'YYYY-MM').

17. Top informants Semi-Pro

joingrouphaving · database: Port Evidence Room

Case request: return each informant's name and total_value (quantity × street_value over all seizures their tips led to, any status), only for informants whose tips were worth more than 500, biggest first.

Hint

Chain the joins: informants to seizures to seizure_items to contraband. GROUP BY the informant, SUM(quantity * street_value), then filter the groups with HAVING (WHERE can't see aggregates).

Show the solution and expected output
SELECT i.name, SUM(si.quantity * c.street_value) AS total_value
FROM informants i
JOIN seizures s ON s.informant_id = i.informant_id
JOIN seizure_items si ON si.seizure_id = s.seizure_id
JOIN contraband c ON c.item_id = si.item_id
GROUP BY i.informant_id, i.name
HAVING SUM(si.quantity * c.street_value) > 500
ORDER BY total_value DESC;

Why it works: WHERE filters rows before grouping. HAVING filters groups after. Four tables joined in a chain give one row per item seized, and SUM rolls them up per informant.

Other databases: Identical everywhere. PostgreSQL and SQL Server don't let you use the alias total_value in HAVING; repeating the expression is portable.

19. Rank the crew Pro

window · database: World Watch-list

Case request: within each country, rank suspects by bounty (highest = 1, ties share a rank). Return first_name, country_id, bounty_usd and country_rank. Skip suspects with no country.

Hint

A window function: RANK() OVER (PARTITION BY country_id ORDER BY bounty_usd DESC). PARTITION BY restarts the ranking for each country.

Show the solution and expected output
SELECT first_name, country_id, bounty_usd,
       RANK() OVER (PARTITION BY country_id ORDER BY bounty_usd DESC) AS country_rank
FROM suspects
WHERE country_id IS NOT NULL;

Why it works: Window functions compute across related rows without collapsing them like GROUP BY does. RANK gives ties the same number (Chris and Felix both carry 118,000) and then skips the next one.

Other databases: Window functions work in PostgreSQL, SQL Server, Oracle, MySQL 8+ and SQLite 3.25+. MySQL 5.7 doesn't have them.

20. Top target per country Pro

ctewindowtop n · database: World Watch-list

Case request: find the single highest bounty in each country. Return the country name (as country), first_name and bounty_usd.

Hint

Number the rows per country with ROW_NUMBER() OVER (PARTITION BY country_id ORDER BY bounty_usd DESC) inside a CTE (WITH ranked AS (...)), then keep WHERE rn = 1. You can't filter on a window function in the same SELECT.

Show the solution and expected output
WITH ranked AS (
  SELECT s.first_name, s.bounty_usd, c.name AS country,
         ROW_NUMBER() OVER (PARTITION BY s.country_id ORDER BY s.bounty_usd DESC) AS rn
  FROM suspects s
  JOIN countries c ON c.country_id = s.country_id
)
SELECT country, first_name, bounty_usd
FROM ranked
WHERE rn = 1;

Why it works: This is the top-N-per-group pattern. Window results only exist after WHERE runs, so you compute them in a CTE or subquery and filter on the outside.

Other databases: Same in PostgreSQL, SQL Server, Oracle and MySQL 8+. PostgreSQL also has DISTINCT ON; Snowflake/BigQuery/DuckDB have QUALIFY.

21. Out-ranking the boss Pro

self join · database: World Watch-list

Case request: find suspects with a bigger bounty than their own boss. Return suspect (first_name), bounty_usd, boss (the boss's first_name) and boss_bounty.

Hint

Join the suspects table to itself: FROM suspects s JOIN suspects b ON b.suspect_id = s.boss_id. Now s is the underling and b is the boss on the same row.

Show the solution and expected output
SELECT s.first_name AS suspect, s.bounty_usd,
       b.first_name AS boss, b.bounty_usd AS boss_bounty
FROM suspects s
JOIN suspects b ON b.suspect_id = s.boss_id
WHERE s.bounty_usd > b.bounty_usd;

Why it works: A self-join treats one table as two, with different aliases. Each row pairs a suspect with their boss, so you can compare the two bounties side by side.

Other databases: Identical everywhere.

22. Chain of command Pro

recursivecte · database: World Watch-list

Case request: map the organization. Return every suspect's first_name and level, where the kingpin (no boss) is level 1, their direct reports are level 2, and so on.

Hint

WITH RECURSIVE chain AS ( start with the kingpin: SELECT ..., 1 AS level FROM suspects WHERE boss_id IS NULL UNION ALL then join suspects to chain ON s.boss_id = c.suspect_id with c.level + 1 ).

Show the solution and expected output
WITH RECURSIVE chain AS (
  SELECT suspect_id, first_name, 1 AS level
  FROM suspects WHERE boss_id IS NULL
  UNION ALL
  SELECT s.suspect_id, s.first_name, c.level + 1
  FROM suspects s
  JOIN chain c ON s.boss_id = c.suspect_id
)
SELECT first_name, level FROM chain;

Why it works: A recursive CTE has a starting query (the anchor) and a step that joins back to itself. Each pass adds the next layer of the organization. It stops when a pass finds no new rows.

Other databases: PostgreSQL, MySQL 8+ and SQLite need WITH RECURSIVE. SQL Server and Oracle write plain WITH. Oracle also has CONNECT BY.

23. Gap between sightings Pro

windowlagdate · database: World Watch-list

Case request: for each suspect with a country, return country_id, first_name, first_seen and days_since_prev: days since the previous suspect first appeared in the same country (NULL for the first one).

Hint

LAG(first_seen) OVER (PARTITION BY country_id ORDER BY first_seen) gives the previous suspect's date. In SQLite, subtract dates with julianday(a) - julianday(b).

Show the solution and expected output
SELECT country_id, first_name, first_seen,
       julianday(first_seen) - julianday(LAG(first_seen) OVER (PARTITION BY country_id ORDER BY first_seen)) AS days_since_prev
FROM suspects
WHERE country_id IS NOT NULL;

Why it works: LAG looks back one row inside the window. The first row in each country has nothing before it, so LAG returns NULL and the subtraction stays NULL.

Other databases: PostgreSQL: first_seen - LAG(first_seen) OVER (...) on DATE columns. SQL Server: DATEDIFF(day, LAG(...), first_seen). MySQL: DATEDIFF(first_seen, LAG(...)).

25. Running seized value Pro

ctewindowrunning · database: Port Evidence Room

Case request: for confirmed seizures in 2024, return each seized_date, that day's seized_value (quantity × street_value) and a running_total across the year, in date order.

Hint

First a CTE that sums value per seized_date (GROUP BY s.seized_date) for confirmed 2024 seizures. Then SUM(seized_value) OVER (ORDER BY seized_date) adds up everything so far.

Show the solution and expected output
WITH daily AS (
  SELECT s.seized_date, SUM(si.quantity * c.street_value) AS seized_value
  FROM seizures s
  JOIN seizure_items si ON si.seizure_id = s.seizure_id
  JOIN contraband c ON c.item_id = si.item_id
  WHERE s.status = 'confirmed'
    AND s.seized_date >= '2024-01-01' AND s.seized_date < '2025-01-01'
  GROUP BY s.seized_date
)
SELECT seized_date, seized_value,
       SUM(seized_value) OVER (ORDER BY seized_date) AS running_total
FROM daily
ORDER BY seized_date;

Why it works: SUM() OVER (ORDER BY ...) is a running total: each row adds up every row up to and including itself. Doing the GROUP BY in a CTE first keeps the two steps easy to read.

Other databases: Same in PostgreSQL, SQL Server, Oracle, MySQL 8+. Add ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW to be explicit when dates repeat.

26. Marseille only Pro

set ops · database: Port Evidence Room

Case request: which contraband items (name) were seized from tips by at least one informant in Marseille but never from a tip by anyone in Rotterdam? Use a set operation.

Hint

Write one query for items seized from Marseille tips and one for Rotterdam tips (same joins, different port), then put EXCEPT between them.

Show the solution and expected output
SELECT c.name
FROM contraband c
JOIN seizure_items si ON si.item_id = c.item_id
JOIN seizures s ON s.seizure_id = si.seizure_id
JOIN informants i ON i.informant_id = s.informant_id
WHERE i.port = 'Marseille'
EXCEPT
SELECT c.name
FROM contraband c
JOIN seizure_items si ON si.item_id = c.item_id
JOIN seizures s ON s.seizure_id = si.seizure_id
JOIN informants i ON i.informant_id = s.informant_id
WHERE i.port = 'Rotterdam';

Why it works: EXCEPT returns rows from the first query that don't appear in the second, and removes duplicates. UNION stacks results and INTERSECT keeps only the rows in both.

Other databases: Oracle calls it MINUS (EXCEPT works from 21c). MySQL added EXCEPT in 8.0.31. PostgreSQL and SQL Server use EXCEPT.
